# Ручные тест-кейсы (Manual Test Cases) — Temfex

Документ содержит набор ручных тест-кейсов для функционального и регрессионного тестирования сервиса временного обмена файлами **Temfex** (Spring Boot 3.4, MinIO S3, PostgreSQL 16, Bucket4j).

### TC-01: Загрузка одного файла и скачивание по временной ссылке

- **Цель**: Проверить базовый сценарий жизненного цикла файла без пароля и ограничений.
- **Предусловия**: Сервис Temfex и хранилище MinIO запущены и доступны (`http://localhost:8080`).
- **Шаги**:
  1. Открыть веб-интерфейс Temfex (`http://localhost:8080`) или отправить `POST /api/files/upload`.
  2. Выбрать одиночный файл `report.pdf` (размером 2.5 МБ).
  3. Нажать кнопку «Загрузить».
  4. Создать ссылку со стандартным TTL (24 часа) без пароля.
  5. Скопировать полученную ссылку формата `http://localhost:8080/s/{shortId}`.
  6. Открыть ссылку в новой вкладке инкогнито и нажать «Скачать».
- **Ожидаемый результат**:
  - Файл успешно сохраняется в MinIO под сгенерированным UUID.
  - В БД сохраняется запись в таблице `files` и `share_links`.
  - По клику на кнопку «Скачать» браузер загружает оригинальный файл `report.pdf` с сохранением имени и корректным MIME-типом `application/pdf`.

### TC-02: Множественная загрузка файлов с генерацией ZIP-архива «на лету»

- **Цель**: Проверить автоматическое объединение нескольких загруженных файлов в ZIP-архив без промежуточного сохранения на локальный диск сервера.
- **Предусловия**: Подготовлены 3 тестовых файла: `doc1.docx`, `image.png`, `notes.txt`.
- **Шаги**:
  1. В форме загрузки выбрать одновременно все 3 файла.
  2. Отправить запрос на эндпоинт `POST /api/files/upload`.
  3. Проверить полученный ответ API.
  4. Сгенерировать ссылку на скачивание и выполнить `GET /s/{shortId}/download`.
- **Ожидаемый результат**:
  - API возвращает `200 OK`, сообщение: `"Архив успешно создан и загружен"`.
  - Имя файла имеет формат архива (`.zip`), MIME-тип `application/zip`.
  - Скачанный ZIP-архив открывается стандартным архиватором и содержит все 3 исходных файла без повреждения содержимого.

### TC-03: Защита ссылки паролем (валидный и невалидный пароль)

- **Цель**: Проверить разграничение доступа к скачиванию файла при установленном пароле.
- **Предусловия**: Файл загружен в систему, получен `fileId`.
- **Шаги**:
  1. Выполнить `POST /api/links` с параметрами: `fileId`, `password: "TemfexPass2026!"`.
  2. Открыть ссылку `http://localhost:8080/s/{shortId}`.
  3. Убедиться, что на странице отображается поле ввода пароля и признак `passwordRequired: true`.
  4. Попробовать скачать файл без пароля: `GET /s/{shortId}/download`.
  5. Попробовать скачать с неверным паролем: `GET /s/{shortId}/download?password=123`.
  6. Отправить запрос с верным паролем: `GET /s/{shortId}/download?password=TemfexPass2026!`.
- **Ожидаемый результат**:
  - При отсутствии пароля или вводе неверного пароля сервер отклоняет запрос с ошибкой (HTTP 403 Forbidden / Error), скачивание не происходит.
  - При вводе верного пароля `TemfexPass2026!` сервер отдаёт файл со статусом `200 OK`.

### TC-04: Ограничение максимального количества скачиваний (Лимит скачиваний)

- **Цель**: Проверить работу счётчика `downloadsCount` и блокировку скачивания при достижении `maxDownloads`.
- **Предусловия**: Файл загружен, получен `fileId`.
- **Шаги**:
  1. Создать ссылку с лимитом `maxDownloads = 2`.
  2. Выполнить 1-е скачивание по ссылке `GET /s/{shortId}/download`.
  3. Проверить статистику по эндпоинту `GET /api/links/{shortId}/stats`.
  4. Выполнить 2-е скачивание по ссылке.
  5. Выполнить 3-е скачивание по той же ссылке.
- **Ожидаемый результат**:
  - 1-е и 2-е скачивания завершаются успешно (HTTP 200).
  - В статистике `downloadsCount` увеличивается с 0 до 2.
  - На 3-й попытке сервер возвращает ошибку «Лимит скачиваний исчерпан» (HTTP 403 / Error), файл не отдаётся.

### TC-05: Истечение срока жизни ссылки (TTL) и фоновая очистка (CleanupService)

- **Цель**: Проверить, что просроченные ссылки блокируются для доступа и удаляются шедулером `@Scheduled(fixedRate = 60000)`.
- **Предусловия**: Запущен шедулер автоматической очистки `CleanupService`.
- **Шаги**:
  1. Создать ссылку с минимальным TTL (`PT1S` или `PT1M`).
  2. Дождаться истечения установленного времени.
  3. Открыть страницу ссылки `GET /s/{shortId}` и попытаться скачать файл `GET /s/{shortId}/download`.
  4. Дождаться срабатывания фонового шедулера (интервал 1 минута) и проверить логи приложения.
  5. Проверить наличие записи в БД (`share_links`) и объекта в корзине MinIO.
- **Ожидаемый результат**:
  - После истечения TTL обращение по ссылке возвращает ошибку «Срок действия ссылки истёк».
  - Шедулер находит просроченную ссылку, удаляет запись из таблицы `share_links`.
  - Если у файла нет других активных ссылок, удаляется запись из таблицы `files` и файл физически удаляется из бакета MinIO.

### TC-06: Защита от спама и DoS-атак через Rate Limiting (Bucket4j)

- **Цель**: Проверить ограничение частоты запросов для предотвращения перегрузки сервиса и исчерпания дискового пространства.
- **Предусловия**: Настроен фильтр `UploadRateLimitingFilter` / `RateLimitingFilter`.
- **Шаги**:
  1. Отправить пакет последовательных запросов на загрузку файла `POST /api/files/upload` с одного IP-адреса, превышающий установленный лимит токенов ведра (например, 20 запросов в минуту).
  2. Зафиксировать HTTP-коды ответов.
  3. Подождать период восстановления токенов (1 минуту).
  4. Повторить одиночный запрос на загрузку.
- **Ожидаемый результат**:
  - Первые запросы в пределах емкости корзины возвращают `200 OK`.
  - При исчерпании токенов фильтр перехватывает запросы и возвращает HTTP 429 Too Many Requests с информативным сообщением.
  - По истечении периода пополнения корзины запросы снова обрабатываются со статусом `200 OK`.

### TC-07: Предпросмотр в браузере (Inline preview) для PDF и изображений

- **Цель**: Проверить корректность отдачи файлов с заголовком `Content-Disposition: inline` для предпросмотра без скачивания на диск.
- **Предусловия**: Загружены два файла: `diagram.png` и `archive.zip`.
- **Шаги**:
  1. Создать ссылку для файла `diagram.png`.
  2. Отправить запрос `GET /s/{shortId}/preview`.
  3. Проверить заголовки `Content-Type` и `Content-Disposition`.
  4. Создать ссылку для файла `archive.zip`.
  5. Отправить запрос `GET /s/{shortId}/preview`.
- **Ожидаемый результат**:
  - Для `diagram.png` ответ `200 OK`, `Content-Type: image/png`, `Content-Disposition: inline; ...`. Изображение рендерится непосредственно в окне браузера.
  - Для `archive.zip` сервер возвращает ошибку (HTTP 415 Unsupported Media Type / сообщение об отсутствии поддержки предпросмотра для данного типа файла).

### TC-08: Генерация QR-кода и переход на страницу скачивания

- **Цель**: Проверить генерацию валидного графического QR-кода, ведущего на страницу скачивания.
- **Предусловия**: Создана активная ссылка с идентификатором `{shortId}`.
- **Шаги**:
  1. Отправить запрос `GET /s/{shortId}/qr`.
  2. Проверить заголовок `Content-Type` ответа.
  3. Сохранить полученное изображение и отсканировать его сканером QR-кодов.
- **Ожидаемый результат**:
  - Сервер возвращает статус `200 OK`, заголовок `Content-Type: image/png`.
  - Бинарное тело ответа представляет собой валидный PNG-файл размером 300x300 пикселей.
  - Декодированный URL совпадает с адресом `http://localhost:8080/s/{shortId}`.
